# MP1 报告草稿：基线分析与参数平均实验假设

> 状态：2026-09-28 完成任务 3。基线结果已测量；EMA 尚未实现、训练或评估。本稿用于后续补充实验，不是最终完整报告，也尚未排版为不超过 10 页的 PDF。

本文目前能够支持的论点是：在固定训练预算下，原始 GPT 的已记录验证 BPB 持续下降，但现有记录不足以证明过拟合、训练末期不稳定或参数平均的收益。下一轮实验将检验，同一训练轨迹的指数移动平均权重能否比最后一步原始权重取得更低的验证 BPB。

## 1. 任务与模型：模型到底在学习什么

任务是在一个最多含 256 个输入 token 的窗口内，根据当前位置及以前的内容预测下一个 token。token 是固定分词器切出的文本单位，不一定是完整单词。例如输入 `[A, B, C]` 时，对应目标为 `[B, C, D]`；预测 C 时不能提前看到 C 或 D。

| 本文用语 | 含义与统一写法 |
|---|---|
| token | 固定 BPE-2048 分词器输出的文本单位 |
| BPB | bits per byte，每个原始 UTF-8 字节对应的平均预测编码长度，越低越好 |
| 训练损失 | 当前随机小批次上的下一 token 交叉熵，单位为自然对数单位/token |
| 原始权重 `θ_t` | 完成第 t 次优化器更新后的模型参数 |
| EMA 权重 `θ̄_t` | exponential moving average，即模型参数的指数移动平均 |
| 同预算 | 相同累计训练目标数；不意味着运行时间和内存一定相同 |

原始模型的数据流可概括为：

```text
token ID → token 向量与位置向量相加 → 4 个 Transformer 模块 → 输出层 → 下一 token 的分数
```

embedding 将离散的 token ID 映射成可学习向量；位置向量说明 token 在当前窗口中的位置。每个模块先通过因果注意力汇集当前及过去位置的信息，再用前馈网络加工特征。残差连接把加工结果加回原特征。输出层为 2,048 个候选 token 给出 logits，训练时通过交叉熵更新参数；评分时将 logits 转成归一化的自然对数概率。

该实现使用 LayerNorm，输入 embedding 与输出层共享权重。以上描述直接对应 [model.py](../code/model.py)，不是新提出的模型结构。

## 2. 已测结果：模型仍在改善，改善幅度逐段减小

基线从随机初始化训练 1,200 步，batch size 为 32，窗口长度为 256，累计处理 `1,200 × 32 × 256 = 9,830,400` 个预测目标。设置固定为 seed 17、CPU、4 线程、FP32，模型共有 1,088,256 个参数。原始优化器、学习率计划、模型和评分器均未修改。

| 训练步数 | 完整验证集 BPB | 相对上个验证点下降 | 相对上个验证点降低比例 |
|---:|---:|---:|---:|
| 300 | 2.331084 | — | — |
| 600 | 2.184163 | 0.146921 | 6.30% |
| 900 | 2.106116 | 0.078047 | 3.57% |
| 1,200 | 2.071087 | 0.035029 | 1.66% |

从第 300 步到第 1,200 步，验证 BPB 共降低 **0.259997，约 11.15%**。四个观测点都下降，末段仍改善 0.035029 BPB，因此不能称模型已经停止学习或完全收敛。逐段增益减小是实际观察；原因可能涉及学习进程及原始学习率衰减等因素，当前实验没有隔离这些解释。

训练日志每 100 步记录一次当时那个随机小批次的损失，共 12 个记录点，全部为有限数值。第 100 步为 5.931262，第 1,200 步为 4.316916；700→800 步和 1,100→1,200 步的记录分别上升约 0.020169 和 0.001801。由于记录来自不同小批次，这些小幅上升不能直接证明同一批数据上的优化退步，更不能当作模型参数震荡的测量。

训练损失与验证 BPB 的样本、单位和统计口径不同，不能直接相减来计算“泛化差距”。这份记录也没有保存每一步参数轨迹、完整训练集评估或中间检查点，因此无法追溯计算过去各步的 EMA。

上述数值来自 [原始训练指标](../code/runs/baseline-s17/metrics.json)，派生计算及证据文件哈希保存在 [baseline_analysis.json](baseline_analysis.json)。冻结基线的测试分数和完整成本另见 [基线记录](../code/BASELINE_RESULTS.zh-CN.md)；本节候选方案的选择依据是训练/验证记录和原始代码行为，没有使用测试分数差异调参。

## 3. 有证据支持的局限，以及尚未证明的解释

原始训练器只导出最后一步权重；验证日志不会自动生成对应的中间检查点。因此，当前流程没有比较“只取训练终点”与“汇总训练期间多步权重”两种导出方式。这是可从 [train.py](../code/train.py) 确认的实现选择，也是下一轮实验要研究的具体问题；它本身不等于终点权重质量已经被证明较差。

**主要假设 H1：** 在训练目标数、模型结构、优化器和数据顺序相同的条件下，对训练后段权重做 EMA，可能比使用最后一步原始权重取得更低的完整验证集 BPB。可能的解释是平均降低了部分随机更新的影响，但目前没有直接测量这种影响。

**竞争假设 H2：** 因为验证表现仍在改善，较早权重可能落后于最后一步；把它们纳入平均可能抵消平滑收益，使 EMA 没有改善，甚至变差。末段验证继续下降使这个失败方向值得预先记录，但也不能仅凭曲线断定 EMA 一定失败。

即使后续 E1 优于 E0，也只直接支持“这条训练轨迹、这个设置下的参数平均取得了更好的验证结果”。它不会单独证明获益一定来自抑制噪声，也不会证明对其他种子或训练预算普遍有效。

## 4. 为什么下一轮先研究 EMA

| 候选方向 | 能回答的问题 | 代价与当前证据边界 | 本轮安排 |
|---|---|---|---|
| EMA | 同一训练轨迹中，平均权重是否优于终点权重？ | 多维护一份参数状态，有训练开销；可导出单个模型进行评分；效果尚未知 | 优先做一对同预算实验 |
| 延长训练 | 额外训练计算能否继续降低 BPB？ | 验证仍下降，值得以后研究；但单纯与 1,200 步比较会混入预算差异，不能替代当前的同预算机制对照 | 暂不混入首轮 |
| 增大模型 | 更多参数能否改善预测？ | 会改变训练和推理成本；当前没有证据把表现局限归因于容量不足 | 暂不混入首轮 |

先选 EMA 的依据是实验对照清楚、改动范围有限、符合课程允许的权重平均路线，而不是已知它必然提高成绩。EMA 是已有的参数平均方法，不将其本身表述为本作业首创。PyTorch 2.7 的 [AveragedModel 官方文档](https://docs.pytorch.org/docs/2.7/generated/torch.optim.swa_utils.AveragedModel.html)说明了独立平均模型的机制；公式可核对 [PyTorch 2.7.1 源码](https://github.com/pytorch/pytorch/blob/v2.7.1/torch/optim/swa_utils.py)。这些来源不提供它在本作业数据与预算下有效的证据。

## 5. 待实施的方法：保持训练过程，另外维护平均权重

保留初始计划已经指定的 `decay=0.99` 和 `ema_start=600`，本次分析不更换这些值，也不称其为最优超参数。第 600 次优化器更新完成后，将那一时刻的原始权重完整复制为 EMA 初始状态；第 601–1,200 步各更新一次 EMA，共 600 次平均更新：

```text
θ̄_600 = θ_600
θ̄_t = 0.99 × θ̄_(t−1) + 0.01 × θ_t，t = 601, …, 1200
```

通俗地说，一套权重继续正常学习，另一套权重缓慢跟随它。两套状态必须独立，EMA 更新不能回写原始模型，也不参与梯度计算。系数 0.99 意味着某一步权重贡献约经过 69 次 EMA 更新衰减一半；这只是公式性质，不是收益证据。

训练结束导出原始 `checkpoint.pt` 与平均权重 `checkpoint-ema.pt`，评价时分别加载一个普通 GPT。它不是把两个模型的预测概率混合，也不在不同评分窗口间积累状态。推理计算图按设计相同，但实际时间、文件大小和峰值内存仍需测量；训练期间维护额外状态的开销也要披露。

现有基线只保存了最后一步权重，不能从这个文件还原真实的历史 EMA。下一轮需要按相同随机种子和训练配方从零训练，并在过程中记录平均权重；不能对同一个最终检查点反复平均后冒充轨迹平均。

## 6. 预先确定的公平对照与判定方式

| 编号 | 状态 | 使用的权重 | 验证 BPB | 累计训练目标数 |
|---|---|---|---:|---:|
| B0 | 已完成并冻结 | 原始基线第 1,200 步 | 2.0710874333793914 | 9,830,400 |
| E0 | 待实施 | 下一次训练的第 1,200 步原始权重 | 尚未测量 | 计划 9,830,400 |
| E1 | 待实施 | 与 E0 同一训练过程的 EMA 权重 | 尚未测量 | 计划 9,830,400 |

E0 和 E1 共用模型初始化、训练小批次顺序、优化器与学习率计划、训练精度、步数及结构。唯一主要差别是导出哪套权重。新增 EMA 跟踪不应消耗影响训练的随机数或改变原始参数更新；实施阶段将检查这一点，并用 B0/E0 的结果排查意外差异。

主要比较量定义为：

```text
Δ = 验证 BPB(E0) − 验证 BPB(E1)
```

- `Δ > 0`：在这一对实验中，EMA 验证表现更好；记录差值与代价，再检查资源约束。
- `Δ = 0` 或差值无法可靠区分于数值误差：没有观察到明确改善。
- `Δ < 0`：这一设置下 EMA 较差，如实报告；不能只凭这个结果断定失败原因。

首轮只运行既定 `decay=0.99`、start=600、seed=17 的一对。若随后有时间，使用计划中预先指定的 seed 23 再做一对，并同时报告两对结果；不只展示最好的种子，也不把一对结果称为统计显著或稳健结论。

E0/E1 的成对比较同时完成相同训练目标数对照与 EMA 机制消融。两者共用一次训练，搜索成本计算一条训练轨迹；但每个导出模型均继承全部 9,830,400 个训练目标，EMA 模型的训练成本不能记为零。其额外平均计算和内存应单独说明。

模型选择只使用验证集，并在资源预检后冻结最终版本，才进行该版本的测试评分。已经冻结的 B0 保持不变，不使用其测试成绩决定 EMA 系数、开始时机或种子。
